# researchflowskills 的开发依据

更新日期：2026-10-29。

这套流程首先解决一件事：将已有数值结果整理成清楚、精致、能够交接的论文图。使用者给出数据、代码或论文相关内容，AI 负责理解需求、选择表达、实现和检查；审美反馈用于改善后续选择，无需逐项批准配色与布局。

## Skills 可以引用 skills，但要写清怎样使用

一个 skill 可以指导 AI 读取或调用其他可用技能。具体方式由运行环境决定：例如 [Claude Code 文档](https://code.claude.com/docs/en/skills)说明模型可以调用可用技能，也允许限制这种调用。因此，在主说明中写一个名字，并不能保证另一技能已经安装、可访问或适合当前任务。

[Agent Skills 规范](https://agentskills.io/specification)没有规定通用的技能依赖安装字段。[OpenAI 文档](https://developers.openai.com/plugins/build/skills)中的 `dependencies.tools` 描述的是 MCP 工具依赖。这里不虚构“引用名称就自动安装”的能力，而是先检查环境，使用能够取得的技能说明；外部资料不可用时，继续执行本仓库提供的基本流程。

## 主流程短，资料按问题读取

科研展示沿用同样方法，一个入口保留“科研图示”“学术汇报”两张卡。共用步骤是理清故事、学习参考、构思选择、实际制作修改、验收；文件格式与素材工具按本次用途选择。外部 skill 的具体入口、配套文件、调用环节与预期输出写入资料卡，结果接回同一份作品，不把多套上游流程整套重复运行。用户已要求由 AI 判断审美，因此第三方默认 A/B 确认不作为新的暂停步骤。

真实数据图和方法关系图按内容分工；出现在 PPT 的误差图仍由 paper-figures 处理，出现在论文的模型总览使用 research-presentation。基金科学论证保留在 grant-writing，共用的制图过程集中在科研展示任务卡。

主说明只保留适用任务、四步流程、必要检查和交付要求。理论、范图、来源及实现细节放在参考文件中，并写明何时读取。资料索引采用“遇到什么问题—查哪里—采取什么动作—怎样检查”的形式，避免每次把整个资料库重新读一遍。

这种组织符合 [Agent Skills 对按需加载和文件引用的建议](https://agentskills.io/specification)：主说明直接指向所需资料，尽量减少层层跳转。只有确实需要稳定计算或反复处理文件的动作才增加脚本。

## 保留内容的结构优化

2026-10-29 根据用户要求仅优化组织与调用方式：触发说明突出任务类型和相邻技能分工，执行细节继续保留在正文或原任务卡。调用提示按本次范围推进，回复模板只在返修时读取，审稿制稿模板只在需要 LaTeX/PDF 时读取；局部改图沿用已核实资料。

科研展示资料分成简短使用方法与详细外部目录，原有来源、配套路径、输出限制和许可说明原文保留，两个文件都从主入口直接可达。需要某个来源时再读其具体部分。其余较短任务卡保持原结构，不为统一形式继续拆分。

同一任务接续不同技能时可以复用已经读取的同版资料，避免重复载入；目标期刊、投稿阶段或材料改变时仍执行原有核实要求。每个技能继续自带相同的语言约定，支持单独安装。真实数据、实际看图、两轮审改、不运行边界和具体交付等关键约束在相应执行与验收位置保留。

## 四步怎样落实

| 步骤 | 要完成的工作 |
| --- | --- |
| 读论文和数据，理清需求 | 将论文主张转成每张图要回答的问题，检查已有结果支持什么；提取单位、误差定义和比较条件。 |
| 查资料、找范例、构思图形 | 按问题选择图种与布局，阅读相关范图和代码；复杂新图按需比较方案，由 AI 选定推荐版本。 |
| 画图、看图、改图 | 从实际数据绘制，打开导出图检查最终尺寸下的文字、图例、色标和裁切，修复具体问题。 |
| 审核与交接 | 分别核对数据对应和图像表达，交付成图、可重画代码、数据来源、处理说明与简短图注。 |

实际执行需要环境能够读取项目文件、运行绘图代码并查看图像。代码运行成功只能说明程序完成执行；数据是否对应、图是否易读，还要分别检查。只改样式时复用已有实验结果。

## 外部技能作为可选帮助

Vivid、Nature、figures4papers 等参考须记录准确来源、适用任务和许可，先确认当前使用方式确实获准。Vivid 默认只保留外部入口；其他来源也不能被本项目的 MIT 重新授权。具体使用范围见可选 skills 说明与第三方来源记录。概念插画的方法与真实数据图的要求分别处理；外部模板的默认字体、配色、面板数量或确认步骤，不自动变成本流程的固定要求。

第三方内容分别保留来源与许可；本仓库的 MIT 声明覆盖原创内容。已完成数据核对和成图检查的本地案例，可以逐渐积累为常用参考。

## 怎样判断开发是否有效

[OpenAI 的测试建议](https://developers.openai.com/plugins/build/skills)同时关注触发是否正确和输出是否合格。验证应包含完整绘图请求、间接表达的改图请求、只调整图例与字号、缺少科学定义、外部技能不可用，以及与绘图无关的请求。

缺少信息时先查现有文件，只有影响科学解释的内容仍不明确才询问。只有图片时，检查结论限于可见内容。格式校验、实际运行和视觉审核的结果分别记录；尚未执行的检查保持待验证状态。后续扩展其他科研任务时，再增加具有清楚用途的小 skill。
