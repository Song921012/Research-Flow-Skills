# 投稿前整理复现仓库

**一句话调用：**“把这些代码、数据和已有图整理成复现仓库，仓库名是……，只整理，不能跑代码。”

## 范围

包含复现论文数值结果所需的代码、可发布数据、已有结果和图，**不包含论文 LaTeX**。将大小写变体的 .tif 和 .tiff 加入忽略规则；已经被 Git 跟踪的文件不能仅靠 .gitignore 排除，也不能擅自删除原始副本。

## 怎么做

1. 先只读看目录、已有入口、配置、路径与 Git 状态，识别正式结果和历史文件。
2. 保留原始工作目录与成果，在独立交付目录整理清楚的代码、数据、结果、图和文档；结构按实际项目需要决定，不堆空目录。
3. 修正写死的个人绝对路径，以项目根目录或明确配置定位。同步整理加载、保存和文档中的路径，静态核对源文件与引用位置。
4. 写清 README：论文与用途、环境依赖、数据来源及获取方式、复现入口与顺序、预计输出、每张图对应的结果和代码、已知限制。只记录从项目证据可知的信息。
5. 在当前已授权的目标仓库发布；否则先交付可审核的本地目录。核对数据、第三方代码和材料能否公开，不把未授权的稿件、私有数据或凭据上传。

## 本卡的硬约定

- **不能执行项目代码，包括实验、训练、测试、绘图、下载数据脚本或编译。**整理文件和做静态文本／路径检查可以进行。
- 可以记录复现命令，不能把“命令已写入 README”说成“已成功运行”。
- 如实写“本次只完成静态整理，未运行验证”；历史验证有证据时另行注明时间与范围。
- 目标是让目录和复现步骤清楚、可继续验证，不能在禁止运行的前提下保证复现成功。

## 交付

整理好的目录、README 与实际可访问的 GitHub 链接（已发布时）；简短列出尚待运行验证或需补充的依赖、数据和路径。
