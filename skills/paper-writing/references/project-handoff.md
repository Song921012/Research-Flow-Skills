# 项目复盘与无缝重启交接

**一句话调用：**“项目暂时告一段落，先只读盘点，再整理半年后也能接着做的交接。”

## 先盘点，再确认

1. 确认项目路径，只读查看 README、论文版本、代码、配置、数据、结果、图片、docs、handoff、归档和 Git 状态。
2. 本阶段不运行实验、训练、测试、绘图或编译，不修改、移动或删除项目文件。
3. 先向用户报告：识别到的当前权威版本、计划读取的关键文件、版本冲突与信息缺口。
4. 按用户对项目交接的约定，**确认后才生成最终指南**。当前对话已有明确确认就继续，不重复询问；这项确认只用于本卡，不扩成其他论文任务的审批。

## 指南应讲清楚的内容

| 部分 | 必须保留的信息 |
| --- | --- |
| 项目概述 | 最初问题、核心科学问题、形成的论文故事、主要贡献和当前阶段 |
| 演化与决策 | 主要阶段；保留、放弃和降为辅助的路线；转向原因和证据 |
| 最终成果 | 论文、附件、代码、数据、结果与图的完成程度；权威入口；冻结结果及它们支撑的结论 |
| 理论与算法 | 关键定义、定理、算法和容易混淆的概念；成立条件、符号、适用范围与不能声称的内容 |
| 数值实验 | 模型、目的、输入、参数、指标、对应图和定量证据；实测／合成数据；正式、pilot、负对照、边界结果；哪些不用重跑 |
| 代码与复现 | 清楚的目录树；结论—图—数据—结果—代码—配置—测试的对应；阅读顺序、入口、环境、种子、精度、设备、路径；区分仅记录和实际验证过的命令 |
| 踩坑与经验 | 理论、实验、叙事、代码、路径、权限、环境与可视化问题的现象、原因、处理和避免办法，特别注明不该重走的路线 |
| 未完成事项 | 必须完成、投稿前完成、可选增强和长期方向；前置条件、影响和风险 |
| 后续研究 | 理论、算法、应用、可辨识性、观测设计和复现等实际相关方向；优先级、新意、工作量及与当前论文的关系 |
| 重启步骤 | 前 30 分钟、第一天、第一周先读什么、检查什么、做什么；修改和重跑前的核对事项 |
| 给下一位 AI | 可直接发送的提示词：先读结论与证据边界，不重走弃用方案，不无理由重跑实验、替换冻结数据或扩大主张；修改前说明依据、范围和验证方式 |
| 一页状态卡 | 一句话目标、核心贡献、权威版本、关键文件和结果、主要限制、优先任务及第一项操作；优先约三项贡献、五个文件／结果、三个限制／任务，有多少可信证据写多少，不凑数 |

## 写法与交付

- 用中文，保留必要英文术语。依据项目实际材料，关键结论指向具体证据文件；可访问时给可点击的绝对路径。
- 清楚区分已经完成并验证、讨论但未实施、被放弃或替换，以及本次提出的建议。记录失败、负结果、边界和缺口。
- 文件冲突要列明并说明为何更信任某个版本；证据不足时不凭文件名猜“最终版”。
- 这份交接可以详细记录工程与复现信息，但不把工程过程写成科学贡献，也不把交接记录塞回论文正文。
- 用户确认后，默认在项目根目录创建 PROJECT_RETROSPECTIVE_AND_RESTART_GUIDE.md；该确认只授权交接文档，不授权整理或重跑项目。已有同名指南时保留历史或按明确要求更新，不覆盖未确认内容。
