# 更新原复现仓库与两个交付包

## 静态更新已有仓库

- 从当前项目 README、论文或用户给定地址定位本论文对应的仓库与分支，有歧义再核实；沿用已授权的目标，不另建替代仓库。
- 先查看目录和 Git 状态，保留已有有效修改、目录、命名、运行入口和图形风格。
- 添加本次已经产生的新代码、中间数据、数值结果和图，核对其与论文、附件的对应关系。更新路径、依赖说明、数据来源和 README。
- **整理阶段不运行项目代码，包括实验、训练、测试、绘图或数据下载脚本。**必要的静态文本、路径和文件对应检查可以进行。
- README 区分本次静态整理和有证据的历史运行验证；不将未运行的命令描述为已经验证。
- 公开仓库仅纳入有发布授权的代码、数据与结果；排除论文 LaTeX、真实审稿意见、回复信、私人信息和凭据。忽略 .tif／.tiff 的大小写变体；已跟踪文件需另行处理，保留原始副本。
- 在当前授权范围内更新 GitHub，核对目标分支与实际发布内容，交付真实仓库链接。

审稿确需的新实验属于此前的研究和改稿工作；这里复用其已保存结果，不因为整理或发布重复运行。

## 默认交付两个压缩包

| 文件包 | 内容 |
| --- | --- |
| manuscript-and-response.zip | 当前修订正文、附件、Bib、所需图与模板文件；按本刊要求准备 clean／marked 及其 PDF；response 的 LaTeX 与 PDF；本次需要的 Cover Letter 等材料 |
| reproduction-repository.zip | 与本次论文结果对应的仓库代码、可发布数据、中间结果、图、依赖说明和 README，不包含论文 LaTeX 与审稿回复 |

文件名可增加简短版本标识。两包对应同一版本；正式提交内容与内部计划、审稿记录分开。最终说明包的用途、GitHub 链接及实际检查范围。用户只要求换模板或局部修改时，交付范围跟随本次请求，不额外制造不需要的文件包。
