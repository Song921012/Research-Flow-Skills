# 收到意见后的返修

**一句话调用：**“按审稿意见在原论文基础上修改，逐条回复，并更新原复现仓库，最后给我两个压缩包。”

## 先看清这次要改什么

读取当前权威正文、附件、编辑信、每位审稿人的全部意见和已有结果。保留原版本；把每条意见对应到需要修改或核查的位置。长任务先列具体计划，再按顺序推进，不等逐项批准。

再次读当前官方返修要求，确认标记方式、clean／marked、回复文件和附件要求。用原稿作为修改依据；旧版只用于有目的的对照。

## 1. 增量修改正文和附件

- 正确内容保持稳定，必要时修 typo；集中修改有问题或需要补充的部分，新增内容精炼，保持原来的论文故事。
- 新增数学结果重点查定义、假设、计算、证明链和所引用的中间结论；修正后同步核对相关结论、正文、附件与回复。
- 新图使用 paper-figures，沿用或协调原稿的配色、字号、标注和多面板风格。实际看图；caption、label、变量和单位应能让读者理解科学含义。
- 新增引用查原始文献、作者题名和 DOI 等信息，保持 Bib 及引用风格一致；不凭记忆补造来源。
- 先使用已有可信数据和结果。审稿意见确需新推导或新实验时，在本次研究范围内完成必要工作，不能把计划写成已完成结果。
- 正文和附件持续执行主说明的学术表达与减少防御性论述约定，保留必要科学细节及证据边界。

## 2. 逐条写 response

读取 [response-style.md](response-style.md) 与 [response-template.tex](../assets/response-template.tex)。保留审稿人编号及每条意见，子问题逐个回应；先完成相应工作，再具体说明实际修改及最终位置。需要时给出新增文字、推导、数据或图，回复的内容要与稿件一致。

意见源于表达不清时，直接说明已补充的定义或解释。采用有根据的替代处理时，说明处理及理由，并在稿件中落实清晰表述。目标是把问题解决并回复清楚，避免反复辩解。

发现缺项就继续处理；仍有实质阻塞时向用户交接具体事项，不把未完成工作写成已完成，也不把未核实的回复当作最终可提交稿。

## 3. 至少两轮实际审改

每轮都完成审稿、修改、academic-research-skills／humanizer 润色和再核对。第一轮重点查意见落实、数学和证据；第二轮重点查遗漏、表述、图文引用与修改后的连锁影响。每轮逐句检查工程笔记式表述和不必要的防御性论述，保持原文结论强度。

最后编译并查看本次需要的正文、附件与 response PDF，在最终排版后核对页码、行号、章节、公式和图号。标记稿只标实际变更；clean 与 marked 的科学内容一致，具体标色服从编辑要求。

## 4. 更新仓库并打包

按照 [repository-and-delivery.md](repository-and-delivery.md)，整理已经完成的新代码、中间数据和结果。默认交付两个同版本压缩包：论文与审稿回复、更新后的复现仓库。内部计划与审改记录不混入提交文件。
