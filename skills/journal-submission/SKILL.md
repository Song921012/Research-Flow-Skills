# 期刊投稿改稿

先读[统一语言约定](references/language.md)。根据本次范围和下文指引读取所需资料；同一任务内已读的同版资料直接复用。

先确认当前权威稿件、目标期刊与投稿阶段，按这次任务读取对应卡。已有明确材料就直接继续；只换模板不加载回复模板或启动仓库更新。

| 这次要做什么 | 读取哪张卡 | 交付什么 |
| --- | --- | --- |
| 改投期刊或按要求换模板 | [投稿换模板](references/change-template.md) | 符合本次投稿要求的正文、附件和文件包 |
| 收到编辑或审稿意见后修改 | [返修与回复](references/revise-and-respond.md) | 修订论文及逐条回复包、更新后的复现仓库包 |

## 一直遵守

- **先读目标期刊当前官网的 Submission Guidelines / Guide for Authors，再动模板。**记录官方链接、核查日期及初投／返修阶段，逐项准备必需材料。必要时参考近期同类型论文的呈现方式；以官方要求和本稿编辑信为准。
- **在原稿基础上修改。**保留正确内容、已有有效修改和原来的故事；必要的新内容精炼、具体，不把修稿变成另写一篇论文。只换模板时，保持科学内容。
- 保留 Bib 文件、引用键及必要的源文件，不擅自修改期刊 .cls。新增文献核实真实性，引用风格与原稿及目标期刊一致。
- 新增或变更的数学结果实际核查定义、条件、计算与证明；新增图调用 paper-figures，与原稿风格协调，caption、label、坐标和符号有具体科学含义。
- 正文、Supplement、Cover Letter 和 response 使用学术表达；运行日志、文件流转、fallback 与 AI 修改过程留在稿件外。必要的模型、离散、噪声、优化和统计细节完整保留。
- 逐句减少不必要的预防性辩解、否定式铺垫和重复免责声明。优先直接陈述发现，把笼统保留改成有依据的具体边界；保留必要不确定性、局限、负结果及相关性／因果性区分，不增强原文结论。

## 返修时的配套资料

- 返修至少两轮实际“审稿—改稿—润色—再核对”，覆盖正文、附件与回复；按需使用 [已有研究、润色和绘图 skills](references/resources.md)。
- 每条回复先有实际完成的修改或核查，再说明做了什么、为什么以及在哪里。保持礼貌直接，用具体内容回答，不以笼统的“已全部修改”代替落实。
- 按 [仓库更新与打包](references/repository-and-delivery.md) 整理已有代码、数据和结果；该阶段不运行项目代码，不把静态整理写成运行验证。

使用 [response-template.tex](assets/response-template.tex)，按 [回复方式与模板用法](references/response-style.md) 填写。模板保留用户常用的版式和逐条回复方式；每次替换成当前稿件的真实信息和已完成工作。

本流程准备可提交材料与复现包。实际提交稿件或向他人发送回复，按用户明确指令执行。
