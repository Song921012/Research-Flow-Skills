# 验收与交接

先查“讲得对不对、能不能看懂”，再查“实际图和页面是否好看、可用”。至少覆盖这两遍，发现问题后修改并重新检查受影响部分；达到任务要求后停止，不为凑轮次反复装饰。

## 第一遍：科学内容与讲述

- 核心信息明确，图中的模块或每页重点服务于故事；没有空泛标题、无意义框图或只有目录却没有解释的页面。
- 逐项核对公式、符号、数字、模块及箭头。方向、端点和关系与原文一致，必要的输入、输出、条件与反馈没有遗漏。
- 创新、效果和结论有材料支持。既有方法与新增部分、拟开展研究与已有结果清楚区分；没有把验证当作推断步骤或把相关性画成因果。
- 数学陈述保留必要假设与适用范围，符号先介绍再使用；删减讲述没有改变命题。
- 数据图与原结果对应，引用真实且与内容匹配。引述的图有来源及适用许可；保留必要不确定性与研究局限。
- 用学术表达讲问题、方法和发现；删除工程日志和无依据的预防性辩解，不增强原结论。

## 第二遍：查看实际成品

- 打开最终导出图或渲染页，以实际使用尺寸检查整图和重点局部；论文按栏宽，基金按正文插图尺寸，报告按投影阅读需要检查。
- 检查文字越框、重叠、截断、缺字、不良断行、箭头压字、连接错误、过小字号、线条过细与对比度不足。
- 检查对齐、间距、留白、视觉层级和颜色含义。图标、阴影与背景有表达用途；主要信息容易被找到。
- 整套报告检查各页顺序与视觉连续性，复杂图逐步展开时位置稳定，导航正确；全新报告逐页看，局部修改核对变化页及受影响页。
- 核对可编辑承诺：PPT 核心文字和对象真实可编辑，SVG/TikZ/draw.io 有相应源结构；整图位图或整图 SVG 嵌入不能充当原生对象验收。
- 核对源文件与最终导出版本一致。Beamer 实际编译、日志和 PDF 相互对应；PPT 核心对象及渲染效果均核查。

## 交付前核对

| 任务 | 应交付 |
| --- | --- |
| 单张科研图示 | 一套推荐成图、可编辑源文件、必要素材与图注或说明 |
| 基金技术路线图 | 原生可编辑 PowerPoint、申请书实际采用的导出图 |
| Beamer 汇报 | `.tex`、所需素材、编译后的 PDF；按需提供讲稿或备份页 |
| PPT 汇报 | 可编辑演示文稿与可用的 PPTX；按需提供 PDF、讲稿或备份页 |
| 提纲或局部修改 | 按本次范围交付，不额外扩成完整报告或多个包 |

简短告知已经完成的内容核对、实际渲染和修改。工具或输入限制留下的缺项应具体说明；没有调用的 skill、没有看过的范图、没有编译或导出的文件不能写成已完成。

在当前项目保留简短的参考来源与选择理由，方便后续修改。默认交一套推荐成品，其他候选留作工作材料；只有用户需要时才展示备选。不要把私人内容、原始参考图或内部检查记录自动发布到公共仓库。
