# 科研展示

先把研究讲清楚，再把图和页面做好看。由 AI 承担参考查找、构思、选版和审美判断，用户反馈辅助校准；不用先让用户挑范图或逐轮批准配色。

| 这次要做什么 | 读取哪张卡 |
| --- | --- |
| 报告流程图、论文方法或模型总览、基金技术路线图 | [科研图示](references/diagrams.md) |
| 整套 Beamer/PPT、汇报提纲、已有幻灯片修改 | [学术汇报](references/slides.md) |
| 选择并实际使用外部 skills、查找优秀范例 | [资料与组合方法](references/resources.md) |
| 完稿、修改后或交付前检查 | [验收与交接](references/review.md) |

## 共同流程

1. **理清故事。**先读材料和已有版本，用一句话确定读者需要明白什么，再理清问题、关键想法、方法关系、证据与结论。按用途确认受众、时长、版面和模板；从现有材料补齐，只追问会改变科学含义或交付的缺项。
2. **学习适合这次任务的表达。**读资料卡，选择相关 skill 并读取必要文件；新图或新报告主动查看少量相关论文、官方范例中的实际图和图注。提取可借鉴的结构、层次和阅读顺序，简单续改不重复大综述。
3. **构思并自己选定。**将故事转成图中的关系或每页的重点；复杂任务在内部比较有实质差异的方案，选出最适合的一套。简短说明理由后继续制作，不默认停下来让用户选 A/B。
4. **制作、看图、修改。**使用适合目标格式的实际工具，保留核心文字、形状、公式与关系的可编辑性。打开真正导出的图或页面，修复具体问题后再查看；不能只交方案或代码，也不能凭代码判断成图合格。
5. **验收与交付。**分两遍核对：先查科学内容与讲述，再查实际视觉和文件。交付一套推荐成品、对应源文件与必要说明，简要说明已经检查什么；只声明实际完成的验证。

## 一直遵守

- 用户本次要求、已有模板和有效修改优先。只改一张图或几页时，保持其余内容与风格，不启动全套重做。
- 故事必须由真实材料支持。保留条件、必要不确定性和结论强度；区别已有结果、研究计划、训练与推断、关联与因果。用学术表达，减少工程笔记和无依据的防御性论述。
- 真实数据图由 paper-figures 处理；本 skill 负责方法图示与整份汇报的整合。基金论证由 grant-writing 负责，本 skill 负责把确定的研究关系画清楚，基金路线图继续用可编辑 PowerPoint。
- 使用外部 skill 时按[资料卡](references/resources.md)检查来源、完整入口和实际能力。原作者优先，确认原库删除或不可用才用已核实的用户 fork；链接不代表已经安装或执行。
- 外部 skill 的默认配色、页数、确认步骤和工具不自动成为本任务要求。按当前环境选择可用工具；某个外部服务缺失时继续独立制作能完成的部分，准确说明实质缺项。
- 私人稿件、图和工作记录留在当前项目。只有用户明确授权公开的材料才加入公共案例；不把借鉴的第三方内容重新标成 MIT。
